# Windows Easy Emoji 계획 3

## 목적

MVP에서 필요한 화면과 상태를 `design.pen`에 구조화한다. 목표는 구현 전에 사용 흐름, 예외 상태, 설정 범위를 시각적으로 합의하는 것이다.

## 결정내용

- `design.pen`에 MVP 화면을 7개 top-level frame으로 정리한다.
- 기본 검색 화면은 `Screen / Search Overlay`로 둔다.
- 검색어가 비어 있을 때의 화면은 `Screen / Search Empty + Recent`로 둔다.
- 검색 결과가 없을 때의 화면은 `Screen / Search No Results`로 둔다.
- 트레이 메뉴 정상 상태는 `Screen / Tray Menu`로 둔다.
- `Win + .` 가로채기 실패 상태는 `Screen / Tray Menu - Hook Failed`로 둔다.
- 설정 화면은 `Screen / Settings`로 둔다.
- 구현 흐름 메모는 `Implementation Notes / MVP Flow`로 둔다.
- MVP 화면은 다크 톤의 Windows 유틸리티 UI로 맞춘다.
- 검색 오버레이는 작은 플로팅 창으로 설계한다.
- 트레이 메뉴는 빠른 상태 확인과 on/off 제어를 중심으로 설계한다.
- 설정 화면은 일반, 동작, 단축키, 정보 섹션으로 나눈다.

## 결정근거

- 이 앱의 핵심 사용 흐름은 `Win + .` 입력 후 즉시 검색하고 붙여넣는 것이다.
- 검색 오버레이는 독립된 작은 창이어야 현재 작업 흐름을 방해하지 않는다.
- 빈 검색 상태는 최근 사용, 즐겨찾기, 인기 기본 이모지를 보여주는 것이 가장 빠르다.
- 검색 결과 없음 상태는 단순한 빈 화면이 아니라 다른 검색 방법과 피드백 후보를 보여줘야 한다.
- 트레이 메뉴는 상주 앱의 상태를 가장 빠르게 확인하고 제어하는 장소다.
- `Win + .` 가로채기는 실패 가능성이 있으므로 실패 상태를 제품 UI에 명시해야 한다.
- 구현 흐름 메모를 디자인 파일 안에 두면 개발 단계에서 화면 의도와 시스템 흐름을 같이 볼 수 있다.

## 선택하지 않은 대안과 이유

- 랜딩 페이지 또는 소개 화면: MVP의 첫 화면은 제품 설명이 아니라 실제 검색 경험이어야 한다.
- 큰 대시보드형 UI: 이 앱은 반복 사용 유틸리티이므로 작은 오버레이와 트레이 중심이 적합하다.
- 밝은 테마 우선 설계: Windows 기본 이모지 패널과 작업 중 오버레이 경험을 고려하면 다크 톤이 덜 방해된다.
- 설정에 모든 고급 옵션 노출: MVP에서는 `Win + .`, 자동 붙여넣기, fallback 단축키, 시작 프로그램 정도만 노출한다.
- 검색 결과 없음 상태를 단순 메시지로 처리: 한국어 별칭 개선 후보를 모을 수 있는 중요한 상태라 별도 화면으로 둔다.
