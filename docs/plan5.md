# Windows Easy Emoji 계획 5

## 목적

검색 오버레이의 새 디자인 컨셉을 정리한다. 목표는 기존의 어두운 네모형 MVP UI를 유지보수하기 쉬운 WPF 구조 안에서 핑크, 주황, 흰색 기반의 귀엽고 아기자기한 이모지 검색 경험으로 바꾸는 것이다.

## 디자인 컨셉

컨셉 이름은 `Soft Kawaii Utility`로 둔다.

이 앱은 빠르게 이모지를 찾아 붙여넣는 Windows 유틸리티이므로, 귀여운 시각 스타일을 입히되 기본 사용 흐름은 방해하지 않는다. 화면은 작은 플로팅 오버레이를 유지하고, 검색 결과는 리스트가 아니라 이모지를 한눈에 훑을 수 있는 그리드로 보여준다. 선택된 이모지는 핑크색 테두리와 밝은 배경으로 강조하고, 상세 정보는 기본 선택 동작을 막지 않는 보조 모달로 제공한다.

`design.pen`에는 기존 `Screen / Search Overlay`를 그대로 두고, 새 비교/구현 기준 프레임으로 `Screen / Search Overlay - Kawaii Grid Concept`를 추가했다.

## 결정내용

- 기본 팔레트는 핑크, 주황, 흰색 계열로 한다.
- 배경은 아주 연한 피치/핑크 톤으로 두고, 주요 패널은 흰색을 사용한다.
- 강조색은 선명한 핑크(`#FF6F91`)를 사용한다.
- 보조 강조색은 따뜻한 주황/피치(`#FFAB80`, `#FFD5CF`)를 사용한다.
- 텍스트는 진한 브라운 핑크 계열(`#3B2430`)을 사용해 밝은 배경에서도 대비를 확보한다.
- 검색 결과는 세로 리스트가 아니라 4열 이모지 그리드로 보여준다.
- 각 이모지 셀은 둥근 카드 형태로 만들고, 이모지와 짧은 한국어 이름을 함께 보여준다.
- 선택된 셀은 핑크 테두리, 흰색 배경, 약한 강조 효과로 구분한다.
- `Enter`와 더블클릭은 기존처럼 바로 붙여넣기 또는 복사 동작을 수행한다.
- 상세 모달은 우클릭, 보조 버튼, 또는 장기적으로 `Space` 같은 별도 동작에서만 연다.
- 모달에는 큰 이모지, 한국어 이름, 동작 힌트, shortcode/한국어 별칭/초성 칩을 보여준다.
- 하단 도움말은 작은 pill 형태로 유지하되, 키보드 흐름과 현재 붙여넣기 상태를 짧게 보여준다.

## 이모지 렌더링 방침

실제 앱 구현에서는 이모지 표시용 `TextBlock`에 `Segoe UI Emoji`를 우선 지정한다.

WPF 텍스트 렌더링에서 이모지가 흰색 또는 단색처럼 보이는 문제를 피하려면 일반 UI 폰트와 이모지 폰트를 분리해야 한다. 이름, 힌트, 상태 텍스트는 기존 Windows UI 폰트 계열을 쓰고, 이모지 glyph만 `Segoe UI Emoji`를 우선 사용하는 스타일로 분리한다.

Pencil 프리뷰에서는 환경에 따라 이모지가 단색으로 보일 수 있지만, 구현 기준은 Windows 실제 컬러 이모지 렌더링이다.

## 검색 결과 그리드

검색 결과 영역은 `ListBox`의 세로 row 디자인에서 그리드형 item panel로 바꾼다.

- 기본 열 수는 4열로 한다.
- 셀은 고정 폭/높이를 사용해 검색 결과가 바뀌어도 레이아웃이 흔들리지 않게 한다.
- 키보드 위/아래 이동은 그리드 기준으로 자연스럽게 동작해야 한다.
- 좌/우 이동은 이후 추가할 수 있지만, MVP에서는 기존 위/아래 순환 선택을 유지해도 된다.
- 결과가 적을 때도 셀 크기와 간격은 유지한다.

## 인터랙션 방침

빠른 입력 도구라는 제품 성격을 최우선으로 둔다.

- 검색어 입력 후 `Enter`: 선택된 이모지를 즉시 붙여넣기 또는 복사
- 더블클릭: 선택된 이모지를 즉시 붙여넣기 또는 복사
- `Esc`: 오버레이 닫기
- 우클릭 또는 보조 상세 액션: 상세 모달 열기
- 상세 모달이 열려도 기본 검색/선택 흐름을 크게 방해하지 않게 한다.

상세 모달은 기능 설명용 큰 팝업이 아니라 빠른 참고 패널이다. skin tone variant, alias, 초성, 최근 사용 정보 같은 보조 정보를 단계적으로 담을 수 있다.

## WPF 구현 메모

- 색상은 `App.xaml` 리소스에 토큰으로 추가한다.
- `MainWindow.xaml`의 전체 구조는 유지하되, 결과 영역의 item template과 panel을 그리드형으로 교체한다.
- 이모지용 스타일과 일반 텍스트용 스타일을 분리한다.
- 셀 hover, selected, keyboard focus 상태를 명확하게 구분한다.
- 모달은 우선 오버레이 내부 `Popup` 또는 조건부 `Border`로 구현한다.
- 모달은 선택 결과의 상세 정보만 보여주고, 기본 paste 동작은 바꾸지 않는다.
- 모달 구현이 복잡해지면 1차 구현에서는 그리드와 컬러/폰트 개선을 먼저 적용하고, 모달은 다음 단계로 분리할 수 있다.

## 결정근거

이 앱의 핵심 가치는 이모지를 빠르게 찾아 현재 앱에 넣는 것이다. 따라서 화면을 귀엽게 만들더라도 landing page나 설명형 UI처럼 흐름을 늘리면 안 된다.

리스트 결과는 이름과 매치 타입을 읽기에는 좋지만, 이모지 도구에서는 시각적으로 훑는 속도가 더 중요하다. 그리드는 같은 공간에서 더 많은 이모지를 보여주고, 사용자가 원하는 표정을 빠르게 알아볼 수 있다.

핑크/주황/흰색 계열은 사용자가 요청한 `초 카와이` 방향에 맞고, 기존 어두운 유틸리티 UI와 명확히 구분된다. 다만 너무 장식적인 배경이나 과한 애니메이션은 Windows 전역 입력 도구의 안정감과 충돌할 수 있으므로 부드러운 카드, 둥근 모서리, 따뜻한 색감 중심으로 제한한다.

## 선택하지 않은 대안과 이유

- 검색 결과를 계속 세로 리스트로 유지: 구현은 쉽지만 이모지 검색 도구의 시각적 탐색성이 약하다.
- 선택 시 항상 모달 먼저 열기: 귀엽게 보일 수는 있지만 붙여넣기까지 단계가 늘어나 핵심 사용성이 나빠진다.
- 5열 이상의 촘촘한 그리드: 더 많은 결과를 보여주지만 작은 오버레이에서 아기자기한 여백과 이름 가독성이 줄어든다.
- 강한 장식형 캔디팝 UI: 개성은 크지만 작은 Windows 유틸리티로 반복 사용하기에는 피로할 수 있다.
- 모든 폰트를 이모지 폰트로 통일: 일반 한글 텍스트 품질이 떨어질 수 있으므로 이모지 glyph에만 적용한다.
