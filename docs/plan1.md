# Windows Easy Emoji 계획 1

## 목적

Windows 기본 이모지 패널(`Win + .`)의 검색 품질, 특히 한국어 검색 부재 문제를 해결하는 가벼운 오픈소스 Windows 앱을 만든다.

## 결정내용

- `.NET` 기반의 가벼운 Windows 네이티브 앱으로 만든다.
- 앱은 트레이에 상주한다.
- MVP는 공격적으로 `Win + .` 대체를 핵심 목표로 잡는다.
- `Win + .` 입력을 감지해 기본 Windows 이모지 패널 대신 자체 이모지 검색창을 띄운다.
- 검색창은 작고 빠른 플로팅 UI로 만든다.
- 한국어, 영어, 초성, 별칭 검색을 지원한다.
- 검색 결과 선택 시 기본 동작은 현재 포커스된 앱에 바로 붙여넣기다.
- 설정에서 자동 붙여넣기를 끄면 클립보드 복사만 하도록 바꿀 수 있다.
- 트레이 메뉴에서 `Win + .` 대체 on/off, 자동 붙여넣기 on/off, 시작 프로그램 등록, 설정, 종료를 관리한다.
- `Win + .` 가로채기가 실패하거나 환경 충돌이 있으면 fallback 단축키를 제공한다.
- 기본 fallback 단축키 후보는 `Ctrl + Win + Space`다.

## 결정근거

- 핵심 페인 포인트는 Windows 기본 이모지 검색이 한국어에서 거의 쓸 수 없다는 점이다.
- 사용자는 기존 습관대로 `Win + .`을 누르기 때문에, 별도 앱을 여는 흐름보다 기본 패널 대체가 제품 가치가 크다.
- 트레이 앱은 항상 실행되어 있어야 하는 전역 단축키 도구에 적합하다.
- `.NET`은 Windows 네이티브 API, 트레이, 클립보드, 키보드 훅, 자동 시작 같은 OS 통합에 유리하다.
- 자동 붙여넣기를 기본값으로 해야 검색 후 입력까지의 흐름이 가장 짧다.

## 선택하지 않은 대안과 이유

- `Tauri + React`: UI 개발은 편하지만 Windows 저수준 통합에서 Rust/plugin 작업이 늘 수 있어 MVP 속도와 단순성에 불리하다.
- `Electron + React`: 구현은 빠르지만 작은 유틸리티 앱치고 무겁고, 가벼운 Windows 앱이라는 목표와 덜 맞는다.
- 안정적인 커스텀 단축키 우선 MVP: 구현 리스크는 낮지만 `Win + .`을 대체한다는 핵심 제품성이 약해진다.
- 클립보드 복사만 기본값: 안전하지만 사용자가 다시 붙여넣어야 해서 기본 이모지 패널 대체 경험이 약하다.
