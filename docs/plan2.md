# Windows Easy Emoji 계획 2

## 목적

Windows Easy Emoji의 이모지 데이터, 검색 방법, 랭킹 정책을 정한다. 목표는 웹 이모지 검색 서비스들의 검증된 방식을 최대한 따라가되, 한국어 검색 품질을 제품의 핵심 차별점으로 만드는 것이다.

## 결정내용

- 1차 데이터는 Unicode CLDR 기반으로 한다.
- 영어/한국어 이름과 키워드를 모두 저장한다.
- GitHub, Slack, Discord 계열에서 널리 쓰이는 shortcode/alias 문화를 참고한다.
- 내부 데이터에는 공식 이름, CLDR short name, 카테고리, 키워드, alias, 한국어 별칭, 초성, skin tone 지원 여부를 포함한다.
- 한국어 별칭 사전은 별도 레이어로 직접 관리한다.
- 검색은 로컬 오프라인 인덱스로 처리한다.
- MVP 검색 입력은 한국어, 영어, 초성, 별칭, shortcode, 이모지 직접 입력을 지원한다.
- 공백, 하이픈, 언더스코어 차이는 검색에서 무시한다.
- 검색어가 비어 있을 때는 최근 사용, 즐겨찾기, 인기 기본 이모지 순서로 보여준다.
- 기본 결과는 노란 기본 이모지와 대표 variant를 우선한다.
- skin tone은 사용자의 기본 설정이나 검색어 단서가 있을 때 우선 반영한다.

## 랭킹 정책

검색 결과는 다음 우선순위로 정렬한다.

1. 정확히 일치하는 한국어 별칭
2. 정확히 일치하는 shortcode/alias
3. 한국어 CLDR 이름/키워드 일치
4. 초성 일치
5. 영어 이름/키워드 일치
6. 부분 문자열 일치
7. fuzzy match
8. 최근 사용/자주 사용 boost
9. 즐겨찾기 boost
10. skin tone/default variant 선호 반영

## 결정근거

- Emojipedia는 공식 이름과 CLDR 기반 의미를 따라가는 대표 서비스다.
- EmojiTerra는 다국어 이름, 태그, 키워드 검색을 제공하므로 한국어 검색 방향의 좋은 참고 대상이다.
- Slack, GitHub, Discord는 shortcode/alias 기반 이모지 입력 문화를 만든 대표 사례다.
- Emojibase는 shortcode가 표준이 아니고 플랫폼마다 다르다는 점을 명확히 하므로, 외부 alias는 참고하되 내부 canonical 구조는 따로 두는 것이 안전하다.
- Emoogle은 keyword, ranking rule, 개인화 autocomplete, skin tone, custom keyword를 강조하므로 장기 방향의 참고 대상이다.
- 핵심 문제는 Windows 기본 검색의 한국어 품질이므로, `ko + en` 검색 품질을 먼저 높이는 것이 가장 중요하다.
- 로컬 인덱스는 빠르고 오프라인 동작이 가능하며, 가벼운 Windows 유틸리티라는 목표와 맞는다.

## 선택하지 않은 대안과 이유

- 처음부터 AI 의미 검색: 자연어 의미 검색은 매력적이지만 MVP에는 무겁고, 속도/배포/비용/오프라인 동작에 불리하다.
- 모든 언어 동시 지원: 범위가 커지고 품질 관리가 어려워진다. MVP는 한국어와 영어에 집중한다.
- shortcode를 자체 표준으로 강제: 플랫폼마다 alias가 달라 사용자 기대와 충돌할 수 있다.
- 서버 검색 API: 동기화와 개선에는 유리하지만, 가벼운 로컬 앱과 오프라인 사용성에 맞지 않는다.
- skin tone variant를 항상 펼쳐서 노출: 검색 결과가 복잡해지고 기본 이모지 선택 속도가 느려진다.
